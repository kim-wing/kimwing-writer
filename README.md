# Kimwing Writer

`kimwing-writer` 是一个面向中文长篇小说与连载网文的 Codex skill。它把小说创作组织成可持续维护的工程：从故事前提、角色、世界观、大纲和章节蓝图，到正文、审稿、修稿、定稿，再到时间线、人物状态、知情范围和伏笔更新。

它不依赖特定小说软件或外部模型服务，直接使用当前 Codex 完成创作与文件管理。

## 主要能力

- 从一句灵感创建完整小说项目
- 组合题材、文笔、叙事视角和节奏
- 生成故事前提、角色图谱、世界观与全书大纲
- 分批规划章节蓝图，避免剧情过早锁死
- 用“立问—加深—部分兑现”设计前三章悬念钩子链
- 强制执行无色情露骨、赌博、毒品、现代现实政治和涉黑内容红线
- 根据正史、角色状态和当前蓝图续写章节
- 检查时间线、人物知情范围、能力边界和因果逻辑
- 维护伏笔、开放矛盾、道具、伤势和角色关系
- 从作者样文提取原创声纹，不复制具体作者
- 诊断套路化、均匀化和常见机械写作痕迹
- 只从定稿更新长期记忆，避免草稿污染正史

## 题材与文笔

题材和文笔是两套独立配置，可以自由组合。

内置题材：

```text
玄幻、仙侠、科幻、奇幻、都市、现代爱情、古代爱情、
悬疑推理、历史、恐怖、现实题材
```

内置文笔：

```text
快节奏连载、冷静克制、细腻情感、古典雅致、电影镜头感、
冷硬锋利、轻松幽默、诗性抒情、纪实写实、群像叙事
```

支持第一人称、第三人称有限、第三人称全知和多视角叙事。例如：

```text
科幻 × 冷静克制 × 第三人称有限
玄幻 × 电影镜头感 × 多视角
现代爱情 × 细腻情感 × 第一人称
悬疑 × 冷硬锋利 × 第三人称有限
```

## 安装

### 让 Codex 安装

在 Codex 中发送：

```text
安装这个 skill：https://github.com/kim-wing/kimwing-writer
```

安装完成后，在新的对话中使用 `$kimwing-writer` 调用。

### 手动安装

```bash
git clone https://github.com/kim-wing/kimwing-writer.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/kimwing-writer"
```

如果目标目录已经存在，请先确认是否需要更新，不要直接覆盖已有自定义内容。

## 严格内容红线

所有题材都默认启用 `strict-clean` 策略，严禁色情露骨、赌博、非法毒品、现代现实政治和涉黑内容。禁区不能作为主线、支线、背景、反派行为或悬念材料。正常克制的爱情描写可以保留，亲密场景只能点到为止或淡出。

古代历史不受政治红线影响，可以写真实历史人物、朝代、官制、战争、外交和宫廷斗争；架空世界的政治冲突也可以写，但不能借古讽今或影射近现代及当代现实政治。

新项目会生成 `style/content-boundaries.md`；每章蓝图必须把五项 `contentSafety` 明确设为 `false`，审稿时还会执行语义检查。旧项目需要先迁移并逐章确认，不能为了通过校验批量填写。

## 使用方法

### 1. 创建新小说

```text
使用 $kimwing-writer，帮我创建一部60章的硬核科幻悬疑小说。
核心灵感是一艘失踪二十年的飞船向地球发送了明天的求救信号。
文笔冷静克制，第三人称有限视角，每章约2400字。
```

skill 会先建立小说工程，再依次完成故事前提、角色、世界观、大纲和近期章节蓝图，不会一次性生成整本书。前三章会作为一个开篇单元规划：第一章立下核心好奇问题，第二章增加线索与代价，第三章兑现部分答案并打开下一阶段。

悬念钩子不等于强行断章。它必须进入人物选择、事件结果或关系变化，不能只在结尾补一句“事情并不简单”。

### 2. 选择题材与文笔

```text
使用 $kimwing-writer，把这部小说设为玄幻主类型、悬疑副类型，
文笔采用电影镜头感与冷硬锋利的混合风格。
```

### 3. 建立作者声纹

```text
使用 $kimwing-writer，分析 sample.md 中我亲自写的文字，
提取句长、段落、对白、心理描写和禁用表达，建立作者声纹。
```

建议提供 2000～5000 字本人样文。skill 只提取抽象技法，不保存大段原文，也不制作具体作家的复制品。

### 4. 续写章节

```text
使用 $kimwing-writer，打开 ./星海来信，检查项目状态，
根据第7章蓝图和前文正史续写正文，不要提前写第8章内容。
```

如果没有当前章蓝图，skill 会先补充蓝图，再进入正文。

### 5. 审稿与修稿

```text
使用 $kimwing-writer，审查 ./星海来信/chapters/chapter-0007/draft.md。
检查正史一致性、角色知情范围、因果、人物声纹和机械化写作痕迹。
先给报告，不要直接改稿。
```

确认问题后可以继续：

```text
根据刚才的报告做最小修改，只处理有证据的问题，不要重写整章。
```

### 6. 定稿与进入下一章

```text
将第7章定稿，更新章节要点、时间线、人物状态、知情范围、
伏笔和开放矛盾，然后准备第8章蓝图。
```

只有定稿内容会进入项目正史和长期记忆。

### 7. 导入旧作续写

```text
使用 $kimwing-writer，把 ./旧作原稿 中的章节整理为小说项目。
保留原文，提取已有设定、时间线、人物状态、未回收伏笔和文风，
从最后一个可靠断点继续规划。
```

## 小说项目结构

```text
小说项目/
├── novel.json                    # 题材、文笔、视角与规模
├── architecture/                 # 前提、角色、世界观和大纲
├── style/                        # 作者声纹、内容红线与负面约束
├── blueprints/                   # 分章蓝图
├── chapters/                     # 草稿、审稿、修订和定稿
├── memory/                       # 时间线、人物状态、伏笔和知情范围
└── exports/                      # 导出内容
```

详细格式见 [`references/project-format.md`](references/project-format.md)。

## 辅助脚本

### 初始化项目

```bash
python3 scripts/init_novel_project.py ./星海来信 \
  --title 星海来信 \
  --genre science-fiction \
  --style restrained \
  --pov third-limited \
  --planned-chapters 60 \
  --words-per-chapter 2400
```

脚本不会覆盖非空目录。

### 校验项目

```bash
python3 scripts/validate_project.py ./星海来信
```

用于检查必需文件、严格内容策略、章节蓝图、前三章钩子链、状态流和定稿资产是否完整。

### 检查机械化写作线索

```bash
python3 scripts/check_prose.py ./星海来信/chapters/chapter-0007/draft.md
python3 scripts/check_prose.py ./星海来信/chapters/chapter-0007/draft.md --json
```

该脚本只标记套话、均匀节奏、固定转场和模板化收束等线索，不能判断文本是否由 AI 生成。

## 关于“去 AI 味”

Kimwing Writer 不以规避检测为目标，也不会通过错别字或随机粗糙感伪装真人。它采用作者声纹、角色声纹、视角纪律、局部诊断和最小修复，让文本具有真实选择与稳定声音。

默认流程是：

```text
发现机械模式 → 引用具体位置 → 确认作者意图 → 局部修改 → 复查正史
```
